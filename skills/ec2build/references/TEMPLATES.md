# Required document content checklist

## PRD.md
Executive summary; confirmed assumptions/unknowns; market/personas; pain points; success metrics; MVP & phases; role matrix; features with IDs (FR-001 etc.), priority and acceptance criteria; nonfunctional requirements (NFR IDs); exclusions; constraints; risks; dependencies; glossary.

## TRD.md
System context; architectural decision records; stack tradeoffs; deployment environments; diagrams; component boundaries; API contracts/error codes; data flows; auth/RBAC; threat model; OWASP mitigations; logging/metrics/tracing; SLOs; compliance assumptions; secrets; integrations/failure modes; performance and accessibility; CI/CD; tests; costs and constraints.

## APP_FLOW.md
Actors, entry/exit conditions, numbered flows each with a **horizontal swimlane** (row per actor/system, left-to-right arrows) generated by `<SKILL_DIR>/scripts/swimlanes.py` from `docs/diagrams/flows.json`, plus its generated Mermaid text version; steps and decisions; success/failure/timeout/retry/access-denied/cancel routes; cross refs to FRs and screens; state transitions.

## DESIGN_BRIEF.md
Design principles; personas; brand direction; token palette & semantic colors; type scale; spacing/breakpoints; navigation IA; screen catalog (IDs), components/states; mobile/accessibility/keyboard/responsive behavior; empty/loading/error states; design acceptance criteria.

## DATABASE_SCHEMA.md
ERD Mermaid; tables with exact columns/types/nullability/defaults/PK/FK; constraints; unique/indexes; tenant isolation/RLS; data retention/privacy; audit trail; backup/recovery; migration & seed strategy; performance considerations; data dictionary mapped to FRs.

## IMPLEMENTATION_PLAN.md
Written as a sequence of self-contained copy/paste prompts (one per TASK, run in order until complete, then a completion audit). Milestone and dependency DAG; ordered phases 0..N; one fully specified coding-agent instruction per task; referenced FR/TRD/flow/design/schema IDs; repository paths; commands and prerequisites; code & docs outputs; tests and security verification; pass/fail criteria; checkpoints, rollback and release gates; progress checklist; no invented completion statuses.

## SETUP.md / setup.json / SHARED_RESPONSIBILITY.md
Per third-party service: purpose, cost note, stages (local/staging/production), steps labelled AUTO / ASSISTED / OWNER-ONLY with exact URLs and commands, env variable names (never values), verification command, troubleshooting. setup.json mirrors it (format ec2build-setup/1). SHARED_RESPONSIBILITY.md: owner / EC2Build / coding agent / provider matrix tailored to the project (see references/SETUP_AND_RESPONSIBILITY.md §6).

## Supporting files
TRACEABILITY.md requirements-to-design-data-code-test mapping; DECISIONS.md architecture and product decisions; CHANGELOG.md edits. manifest.json metadata with each document's state/version and dependency relationships.
